第四步 **「质量闭环、写作辅助与个人知识资产层」**（智能查词、写作润色 Diff、反向回译校验、翻译记忆库、TTS 朗读与生词本/Anki 闭环）。

做完前三步（管道底座、系统级划词/截屏、批量多图与文档工作台）后，软件已经全面解决了「看懂外文」**；第四步的价值在于把软件从「一次性消耗型翻译器」升级为**「能读、能查、能写、能校、能沉淀的双向语言工作台」**。更重要的是，这一层全部基于纯 Python 与 SQLite 实现，依然严格维持**轻核心体量，不会引入几百 MB 的重型推理依赖（重型 PDF 排版分析、本地 OCR 贴片、WASAPI 实时语音字幕留到第五步做成「按需下载扩展包」收官）。

## 二、五大核心模块开发思路与避坑要点

### 模块 1：智能查词与双层词典视图（`app/core/dictionary/`）

普通翻译软件查单个单词时，大模型经常只吐一个孤零零的中文词，既没音标也没词性变形。这一步给主窗口和第二步的「划词浮窗」加上**自动词典视图**：

- **精准分流（`detector.py`）**：输入去除首尾空格后，若满足「不超过 3 个英文单词、不含句末标点且非 URL/代码路径」，自动切入词典视图；顶部保留一键切换回「整句翻译」的按钮，避免误判。
- **离线秒出 + AI 异步补全**：
  - **第一层（毫秒级）**：本地查询可选下载的 **ECDICT SQLite** 精简词库（压缩后约 25 MB，放在 `%LOCALAPPDATA%\IndexTranslate\dict\`，缺失时自动跳过），瞬间渲染英/美音标、词性分组释义、词形变化（复数/过去式）以及考纲标签（CET6/IELTS/GRE）。
  - **第二层（流式补全）**：后台并发向 `TranslationPipeline` 发一条轻量指令请求（默认用 `9B` 或 `2B`），异步补充「地道固定搭配、近义词微差、2 句双语例句」，两层拼装在同一张 `dict_card.py` 里，既快又有深度。



### 模块 2：写作润色 Diff 对比与反向回译校验（`app/core/polish/`）

这部分对标 DeepL Write，直接打通「用外文写邮件、论文、PR 描述」的高频刚需：

- **多风格润色预设**：复用你现有的「可选指令」架构，内置 5 套结构化风格模板——`语法纠错（最小改动）`、`商务邮件`、`学术严谨`、`地道口语`、`精简压缩`。
- **中英混合词级 Diff（`diff_engine.py`）**：
  - **避坑点**：不要直接对字符串按字符做 `difflib.SequenceMatcher`，否则英文单词改一个字母会碎成一片红绿噪点；也不能简单按空格 `split()`，否则中文完全无法按字比对。
  - **正确做法**：用正则 `r"[A-Za-z0-9_']+|\s+|[^\sA-Za-z0-9_']"` 先切分成 Token 序列再算 Diff，把删除段包成浅红底删除线、新增段包成浅绿底高亮，直接喂给 `QTextBrowser` 渲染，并在右侧或下方附带「核心改动说明」。
- **2B 极速反向回译校验**：在普通翻译结果的底部加一个可折叠的「反向回译核验」小栏。开启后，主译文生成完毕时后台自动用 `Index-Translate-2B` 把译文悄悄翻回用户的源语言。写重要商务邮件或外文公告时，一眼就能看出语气有没有变硬、意思有没有跑偏。



### 模块 3：翻译记忆库（Translation Memory）与 Few-Shot 注入（`app/core/memory/tm_db.py`）

翻译记忆库是专业 CAT 工具的核心护城河，能把用户过去在主窗口和第三步批量工作台里**手工微调过的译文**变成长期复利资产：

- **数据来源**：只要用户在主窗口或批量审校表里手动编辑并确认了某条译文，自动写入 `tm_db.py` 并打上 `reviewed = 1` 标记。
- **两段式高速模糊匹配**：
  1. 先用 SQLite 自带的 **FTS5 全文索引**做粗召回（取前 20 条候选，百万级数据也能控制在 5 ms 内）；
  2. 再用 `rapidfuzz`（纯 C++ 编译轮子，体积不到 2 MB）对这 20 条算编辑距离相似度。
- **挂载到第一步的 `TranslationPipeline` 前置钩子**：
  - **100% 精确命中已审校记录**：直接返回记忆库译文（零延迟、零接口消耗），UI 显示 `记忆库命中` 微标并支持点「强制重译」。
  - **75%–99% 高相似命中**：不强行覆盖，而是把最相似的 1–2 对 `(历史原文 → 已审校译文)` 拼进本次 Prompt 作为 Few-Shot 参考，模型会自动对齐你一贯的术语和行文口径。



### 模块 4：零成本高自然度 TTS 朗读（`app/core/tts/tts_service.py`）

- **主通道（在线高质量）**：接入 `edge-tts`（纯 Python 异步库，几乎不占打包体积），免费提供微软神经网络人声，支持美音/英音/日音等多口音与倍速调节；合成后的 MP3 按 `(text_hash, voice, rate)` 存入本地缓存目录，重复点击播放零网络请求。
- **离线兜底（断网不报错）**：网络异常或离线查词时，自动无缝回落到 Windows 自带的 `SAPI.SpVoice`（直接复用仓库已有的 `pywin32` 调用 `win32com.client`）。
- **播放器集成**：用 PyQt6 自带的 `QMediaPlayer` + `QAudioOutput` 播放，点击同一按钮再次触发即停止播放，避免多段语音重叠串音。



### 模块 5：生词本与 Anki 复习闭环（`vocab_db.py` + `anki_exporter.py`）

- **带上下文一键收藏**：在划词浮窗、词典卡片或主窗口选中任意生词点「星标」，不仅存单词和释义，还**自动抓取当前正在翻译的整段原句作为记忆语境**，附带来源应用名（第二步 `pywin32` 已能拿到）和时间戳。
- **双通道导出复习**：
  - **轻量直连（推荐）**：通过 `httpx` 向本地 `AnkiConnect`（默认 `[http://127.0.0.1:8765](http://127.0.0.1:8765)`）发送 `addNotes` JSON-RPC 请求，内置查重逻辑，一键把新收藏生词同步到指定牌组。
  - **通用离线导出**：支持导出标准 UTF-8 BOM 的 CSV / TSV（带正面、背面、音标、例句、标签五列），直接兼容 Anki、欧路词典和墨墨背单词导入。

## 三、开发节奏与验收清单

建议按 4 个独立小闭环顺序合入，每一步都能立即可用：

1. **闭环 A（查词 + 朗读）**：实现 `detector.py`、`ecdict_db.py`、`tts_service.py` 和 `dict_card.py`，把词典视图和发音按钮同时接入主窗口与划词浮窗。
2. **闭环 B（写作润色 + 回译校验）**：实现 `diff_engine.py`、`polish_service.py` 和 `polish_page.py`，并在主翻译页底部加上可开关的「2B 反向回译校验栏」。
3. **闭环 C（翻译记忆库）**：实现 `tm_db.py`（FTS5 + RapidFuzz），挂接到 `TranslationPipeline` 前置钩子，打通「批量审校/主窗改译文 → 自动入库 → 下次复用」。
4. **闭环 D（生词本与 Anki）**：实现 `vocab_db.py`、`anki_exporter.py` 和 `vocab_page.py`，补齐星标收藏、标签筛选和 AnkiConnect 同步。
